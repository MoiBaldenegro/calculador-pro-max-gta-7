- 2026-11-24 — Descubrimiento (issue #1): producto definido en `docs/vision.md`. Es una calculadora científica web + graficador de funciones `f(x)`, 100% estática, vanilla HTML/CSS/JS con Canvas 2D, desplegada en GitHub Pages. Interfaz en español.
- 2026-11-24 — Supuesto clave: "gráficas algorítmicas" se interpretó como graficar funciones matemáticas de una variable (plano cartesiano, zoom y paneo), no como visualización de algoritmos/estructuras de datos. Si el humano corrige esto, revisar alcance del MVP.
- 2026-11-24 — Restricciones de producto: sin backend, sin login, sin persistencia en servidor; se acepta perder historial/gráficas al recargar. Fuera de alcance: CAS, resolución simbólica, multi-idioma, dominio propio.
- 2026-11-24 — Planificación (issue #2): arquitectura y backlog en `docs/architecture.md` y `docs/backlog.md`. Decisiones clave: parser propio (tokenizer + descenso recursivo → AST + evaluador, sin `eval`); ángulos en **radianes**; multiplicación implícita (`2x`, `2sin(x)`); errores tipados `{ok,value}|{ok,error{type,message,position}}` (graficador ignora NaN/Inf por punto); graficador con escala uniforme y muestreo por píxel; GitHub Pages vía GitHub Actions (artefacto) con **rutas relativas** por el subpath `/calculador-pro-max-gta-7/`.
- 2026-11-24 — Tests sin dependencias: runner nativo `node --test` (Node 26 disponible en la máquina). No hay paso de build. Ejecutar en local con `python -m http.server 8080` (ES modules no cargan en `file://`).
- 2026-11-24 — F2 (motor de expresiones, issue #4): implementados `js/expr/{functions,tokenizer,parser,evaluator}.js` sin `eval`/`new Function`. API pública: `parse(texto)` → `{ok,value:AST}|{ok:false,error}`; `evaluate(ast, env={})` → `{ok,value}|{ok:false,error{type,message,position}}`. `tokenize` devuelve `Token[]` y solo lanza (con `.position`) ante carácter inválido; `parse` lo captura. Nodos AST llevan `position` (se usa para errores de dominio/eval). `parser` importa `functions.js` (rompe la columna de dependencias de §3, pero es necesario para distinguir constante/variable/función); `functions.js` no importa nada, sin ciclos. Multiplicación implícita resuelta en `term` cuando el siguiente token es number/identifier/lparen. Ángulos en radianes. `^` asociativo a la derecha (exponente = `parseUnary`), menos unario por debajo de `^` (`-2^2=-4`). Errores de dominio: división por cero, `inDomain` de sqrt/log/ln/asin/acos y cualquier resultado NaN/±Infinity → «Resultado no definido». `x` sin valor en `env` = error de dominio. Tests: 45/45 en verde.
- 2026-11-24 — F1 (esqueleto): creados `index.html`, `css/styles.css`, `js/app.js`, `js/calculator.js`, `js/grapher.js`, `js/coords.js`, `js/expr/{tokenizer,parser,evaluator,functions}.js` como stubs documentados con JSDoc. `package.json` usa `"type": "module"` (necesario para que `node --test` trate los `.js` como ES modules) y `"test": "node --test test/"`. Tests smoke en `test/` solo comprueban que los módulos puros cargan y exportan sus funciones; no llaman a los stubs (que lanzan `Error` "no implementado" hasta F2/F4/F5). `app.js` monta las dos secciones y actualiza `#estado`; no invoca el motor, así que la página carga sin errores.
